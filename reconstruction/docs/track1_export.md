# Export a CARI4D episode for Track 1

The adapter reads a completed wild-inference episode, decodes its refined MHR
human, and invokes the **official submission kit's**
`tools/track1/mesh_to_mhr_params.py`. It produces the episode NPZ, the aligned
object GLB, and an export report. It does not rerun video reconstruction or submit
to Kaggle. It requires the CARI4D runtime and weights; GPU execution is recommended
for the official fitter.

## Why the conversion needs fitting

CARI4D stores continuous pose controls plus per-frame shape and 28 scale
coefficients. The kit expects 136 pose parameters per frame, **one** 45-value
shape vector and **one** 68-value scale vector per episode. Taking a frame or
averaging these fields is not a lossless conversion.

The adapter uses the existing `MHRLayer` to decode all refined frames to MHR lod1
vertices in metres. Those vertices already use the official converter's axis
convention: `diag(1,-1,-1) @ MHR(...) / 100`, with the CARI4D world translation
included. The converter fits a constant identity and zero expression. It can
change the human geometry; the report measures this added error explicitly.

Object rotation/translation are retained in the same world frame. The exported
mesh is `export/<episode>/object_mesh/output_aligned.glb`, whose physical scale
has already been established; the submitted `object_scale` is `1`. Substituting
the original SAM3D mesh would invalidate these poses. The official packer applies
the competition's mesh budget later.

## Inputs and invocation

- `result_dir`: the episode directory containing `pipeline_report.json`,
  `inference/refined.pth`, and `export/episode_XXXXXX/object_mesh/output_aligned.glb`.
  Only load trusted artifacts generated by this pipeline (Torch/pickle format).
- `submission_kit`: an unpacked official kit containing the mesh fitter.
- `weights_path`: the same persistent CARI4D weights directory used for inference,
  including SAM3D body buffers/checkpoint and `assets/mhr_model.pt`.
- `output_dir`: a **new**, empty destination name. Existing directories are refused.
- Supply the actual inference business commit, image build commit, and image
  digest. The adapter independently fingerprints its current Python sources,
  the converter, model, result bundle and mesh. These records describe different
  parts of the experiment and must not be interchanged.

Inside the CARI4D environment, after the new adapter code is available:

```bash
python -m v2d.cari4d.lib.export_track1 \
  --result_dir /data/results/episode_000016 \
  --submission_kit /data/v2d_submission_kit \
  --weights_path /data/weights/cari4d \
  --output_dir /data/exports/run-001/episode_000016 \
  --episode_index 16 --expected_frames 360 \
  --business_commit "$BUSINESS_COMMIT" \
  --image_build_commit "$IMAGE_BUILD_COMMIT" \
  --image_digest "$IMAGE_DIGEST" \
  --max_vertex_error_mm 1.0 --conversion_error_policy report
```

Set the three version variables to your actual experiment record. On a Docker
host, use `v2d.cari4d.docker.run_export_track1` with the same options; `--dev`
mounts the checked-out modules. In a GPU Pod, invoke the library directly.
If the image predates this adapter, execute the checked-out
`reconstruction/modules/v2d_cari4d/lib/export_track1.py` with these same flags.
Simply cloning the branch does not change the installed Python package.

The decoder and fitter run in separate processes so decoder VRAM is released
before fitting. `--decode_batch_size` defaults to 16, `--fit_model_batch_size`
to 128, and `--fit_precision` to `float64`. The fitting time is additional to
the original eight-stage reconstruction time.

## Acceptance and outputs

The adapter requires all original frames, consistent source-frame metadata,
finite parameters, proper object rotations and an unambiguous aligned mesh.
The **1 mm reference tolerance measures the worst frame's mean vertex
displacement introduced by conversion**. It is an engineering reference, not a
competition threshold or a ground-truth accuracy score. Invalid frames may not
be silently filled by the fitter. Choose an explicit conversion policy:

- `reject` (API/CLI default): do not publish an export above the reference tolerance.
- `report` (current baseline decision): publish structurally valid outputs and
  record the measured error, whether the tolerance was exceeded, and which frames
  exceeded it. This changes acceptance only, not the converter or its parameters.

The baseline invocation above deliberately selects `report`. It keeps the
existing official fitting algorithm while deferring conversion-precision
optimization. Both modes reject invalid/omitted frames, malformed dimensions,
non-finite or negative errors, and invalid object motion. No threshold is an
estimate of Kaggle score loss, and successful packing is not an accuracy result.

A successful export contains:

```text
episode_000016.npz
episode_000016_object.glb
episode_000016_export.json
```

The JSON includes per-frame fitting errors, decoder identity, source/input/output
hashes, version records, fitting settings and an explicit `acceptance` record.
`accepted_for_packing` refers to this export policy, not user review, repository
merge approval, or a competition score. Inputs changing during conversion
cause failure. On failure, the destination is not published; the error names a
hidden sibling work directory containing intermediate artifacts available so far, such
as `human_vertices.npy` and `human_fit.npz`. Inspect these before changing the
tolerance. Exports are never implicitly reused.

One call exports one episode. A full submission must collect validated NPZ/GLB
pairs for **every** required episode in one directory and pass the official full
sample roster to `eval_reconstruction.py`. The single-episode folder alone is
not a valid full competition submission.

## Validation scope

CPU adapter tests exercise timeline/geometry contracts, failure isolation,
provenance, wrapper parity and the actual official packer with synthetic fitted
parameters. They do **not** run the MHR model or official nonlinear fitter.
Real episode fitting, overlay review and conversion-error acceptance still need
the CARI4D runtime plus weights. A packed Parquet is not a Kaggle score.

The repository-level kit integration test is separate from the module container
suite because that container does not mount `docs/`. In an isolated host test
environment with numpy, scipy, trimesh, pytest, pandas, pyarrow and
fast_simplification installed, run from the repository root:

```bash
python -m pytest reconstruction/modules/v2d_cari4d/tests/test_track1_export.py tests/test_track1_kit_integration.py -q
```
